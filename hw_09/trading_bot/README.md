# Торговый бот BTC/USDT perpetual на Bybit: CatBoost + стоп-лосс 3%

Бот торгует бессрочным фьючерсом **BTCUSDT (linear)** на Bybit по стратегии из ноутбука
`../final_ensenble_with_sltp.ipynb`: **CatBoost + стоп-лосс 3% без тейк-профита**. В разделе 25
ноутбука эта связка лучшая: в среднем +4.3% по шести окнам walk-forward при рынке −2.6%.

> ⚠️ Ключи в `.env` — от **реального счёта (mainnet)**. Все ордера исполняются на реальные деньги.
> Сам ноутбук предупреждает, что результаты бэктеста не основание для торговли реальными деньгами.

## Конвейер данных и формирование рекомендации

Бот работает по расписанию, без внешних очередей и баз: каждый час, через 20 секунд после
закрытия часовой свечи, он прогоняет весь конвейер заново, от сырых свечей до ордера.

```
 Bybit REST (через прокси)
   │  /v5/market/kline, 2 запроса × 1000 свечей
   ▼
 ① Загрузка и проверка данных ──────────── fetch_bars()        ✗ разрывы / мало истории → итерация прерывается
   ▼
 ② Признаки (18 шт.) ───────────────────── features.build_features() + finalize()
   ▼
 ③ Предобработка ───────────────────────── винзоризация по границам dev, проверка NaN   ✗ NaN → прерывается
   ▼
 ④ Модель ──────────────────────────────── CatBoost → p(рост на следующем часе)
   ▼
 ⑤ Торговый слой ───────────────────────── strategy.target_positions(): EWM, пороги, hold, ребалансировка
   ▼
 ⑥ Правила выхода ──────────────────────── блокировка после стоп-лосса до смены знака цели
   ▼                                        = РЕКОМЕНДАЦИЯ (recommended: LONG / SHORT / FLAT)
 ⑦ Риск-менеджер ───────────────────────── risk.py: стоп торговли, пауза, вето на действие
   ▼                                        = РЕШЕНИЕ (desired)
 ⑧ Исполнение ──────────────────────────── рыночный ордер + стоп-лосс 3% на позиции
   ▼
 ⑨ Журналы ─────────────────────────────── runtime/state.json, logs/signals.csv, logs/trades.csv, bot.log
```

### ① Загрузка и проверка данных

- Бот скачивает 2000 последних часовых свечей BTCUSDT (open, high, low, close, volume) через
  `GET /v5/market/kline` двумя страницами по 1000 штук.
- Текущая незакрытая свеча отбрасывается: решение принимается только по завершённым барам.
- Проверки: сетка без разрывов (ровно 1 час между свечами) и не меньше 700 свечей. При нарушении
  итерация прерывается и через 60 секунд повторяется, ордера не отправляются.

### ② Признаки

Формулы перенесены из ноутбука без изменений. Считаются только 18 признаков, прошедших отбор
(раздел 12.2, «мягкий отбор»):

| группа | признаки |
|---|---|
| доходности | `ret_1`, `ret_2_atr`, `ret_3`, `ret_6`, `ret_6_atr`, `ret_lag_1` |
| скользящие средние | `close_ema5_ratio`, `sma5_slope`, `close_sma10_ratio`, `close_sma10_atr` |
| геометрия свечи | `lower_frac`, `clv`, `body_atr`, `shadow_imbalance` |
| канал Дончиана | `donchian_pos_55` |
| вейвлет / CWT | `wl_e_d4` (db4, окно 256 ч), `cwt_e_72p` (Морле, окно 256 ч) |
| новости | `news_count_168` — всегда 0 (см. «Ограничения стратегии») |

Все окна смотрят только назад: признак бара `t` зависит от баров `≤ t`. В ноутбуке это проверено
тестом на утечку (раздел 7.4). Первые 600 баров истории уходят на прогрев окон, прогнозы по ним
не используются.

### ③ Предобработка

- `inf` заменяется на `NaN`, пропуски заполняются вперёд, остаток — нулём (как в ноутбуке).
- **Винзоризация:** каждый признак обрезается по квантилям 0.1% и 99.9%, посчитанным на
  обучающей выборке (`artifacts/meta.json`). Значения вне диапазона обучения не уводят модель
  в экстраполяцию.
- Если после этого в признаках остался `NaN`, рекомендация не формируется.

### ④ Модель

CatBoost (`artifacts/catboost.cbm`) выдаёт вероятность `p` того, что close следующего часа
будет выше текущего. Прогноз считается для всех ~1400 баров окна, а не только для последнего:
так торговый слой видит историю сигналов и восстанавливает своё состояние после перезапуска.

### ⑤ Торговый слой: вероятность → целевая позиция

Параметры подобраны Optuna для CatBoost (раздел 15 ноутбука):

1. **Сглаживание:** `p_ewm = EWM(p, span = 4)` гасит однобаровый шум.
2. **Пороги:** `p_ewm ≥ 0.5378` даёт сигнал **LONG**, `p_ewm ≤ 0.4677` — **SHORT**. Пороги — это
   квантили 98% и 2% сглаженных прогнозов модели на обучающей выборке, то есть уверенной
   считается примерно 2% часов с каждой стороны.
3. **Режим hold:** между порогами держится последний уверенный сигнал.
4. **Ребалансировка раз в сутки:** целевая позиция берётся из сигнала на свече, которая
   закрывается в 00:00 UTC, и держится до следующей полуночи.

### ⑥ Правила выхода → рекомендация

Если позицию закрыл стоп-лосс, сторона блокируется: рекомендация остаётся FLAT, пока целевая
позиция не сменит знак (`cooldown = -1`, как в `_exit_kernel` ноутбука). Итог шагов ⑤–⑥ —
**рекомендация** `recommended` (колонка в `signals.csv`).

### ⑦ Риск-менеджер → решение

Рекомендация проходит через ограничения из раздела [«Ограничения риска»](#ограничения-риска).
Риск-менеджер может:
- остановить торговлю и закрыть позицию;
- поставить паузу до конца суток;
- запретить конкретное действие;
- урезать размер позиции.

Итог — **решение** `desired`. Если действие запрещено, в `signals.csv` записываются
`action = vetoed` и причина в колонке `veto`.

### ⑧ Исполнение

- Если решение совпадает с позицией на бирже, ордеров нет. Бот только проверяет, что на позиции
  стоит стоп-лосс, и при необходимости восстанавливает его.
- Иначе бот закрывает текущую позицию рыночным `reduceOnly`-ордером и открывает новую рыночным
  ордером. Стоп-лосс ставится сразу в ордере, затем выравнивается ровно на 3% от фактической
  цены входа (`/v5/position/trading-stop`, триггер LastPrice). Тейк-профита нет.
- Размер позиции: `min(POSITION_FRACTION × equity, MAX_POSITION_USDT)`, округление вниз до шага
  0.001 BTC.

### Между итерациями

Каждые `RISK_CHECK_SEC` секунд (по умолчанию 60) идёт лёгкая проверка без модели:
- не закрыл ли позицию стоп;
- equity против лимитов просадки и суточного убытка;
- рубильник `HALT`;
- наличие стоп-лосса на позиции.

Каждая проверка обновляет `runtime/heartbeat`, по нему Docker определяет, жив ли бот.

### Соответствие ноутбуку

`train.py` повторяет обучение из ноутбука и сверяет бэктест шагов ②–⑥ с его числами:

| отрезок | SL 3%, без тейка | buy & hold |
|---|---|---|
| валидация (08.10.2024 — 04.06.2025) | +71.7%, Sharpe 1.86 | +68.0% |
| бычий / боковой | +4.7% / −3.2% | +11.7% / +1.6% |
| медвежий / медвежий-2 | −3.2% / −3.2% | −30.5% / −30.9% |
| боковой-2 / бычий-2 | −3.2% / +33.6% | −0.2% / +32.6% |
| **среднее по 6 окнам walk-forward** | **+4.3%** | −2.6% |

На пересекающемся периоде вероятности по свечам Bybit совпадают с расчётом по
`data/btc_1h.csv` бит в бит.

## Ограничения риска

Ограничения защищают капитал, если модель будет рекомендовать неоптимальные действия. Они
задаются в `.env` (реализация — `risk.py`) и действуют поверх стоп-лосса 3% на каждую сделку.

| параметр | по умолчанию | что происходит при срабатывании |
|---|---|---|
| **Стоп торговли** | | позиция закрывается, торговля остановлена до ручного возобновления |
| `MAX_DRAWDOWN_PCT` | `20` | equity упало на 20% от максимума |
| `MIN_EQUITY_USDT` | `80` | equity ниже 80 USDT |
| `MAX_CONSECUTIVE_LOSSES` | `3` | три убыточные сделки подряд (прибыльная сделка сбрасывает счётчик) |
| — | — | стоп-лосс на новую позицию не удалось поставить или восстановить |
| — | — | создан файл `runtime/HALT` (ручной рубильник, `--halt`) |
| **Пауза до 00:00 UTC** | | позиция закрывается, новые сделки запрещены до конца суток |
| `DAILY_LOSS_PCT` | `5` | equity упало на 5% от значения на начало суток UTC |
| **Вето на действие** | | сделка не выполняется, текущая позиция остаётся как есть |
| `MAX_TRADES_PER_DAY` | `4` | за сутки UTC уже открыто 4 позиции |
| `MAX_DATA_DELAY_MIN` | `90` | последняя закрытая свеча старше 90 минут |
| `MAX_PRICE_DEVIATION_PCT` | `2` | close свечи и текущая цена расходятся больше чем на 2% |
| **Размер** | | |
| `MAX_POSITION_USDT` | `150` | позиция урезается до 150 USDT |
| `MAX_LEVERAGE` | `3` | потолок для `LEVERAGE` |
| `RISK_CHECK_SEC` | `60` | частота проверок между часовыми итерациями |

Как устроены лимиты:

- **Equity** — капитал в USDT с учётом нереализованного PnL. Пик и база суток хранятся в
  `runtime/state.json` (блок `risk`) и переживают перезапуск.
- **Возобновление после стопа торговли.** При любой остановке бот создаёт файл `runtime/HALT`
  с причиной. Чтобы возобновить торговлю, удалите файл или выполните `--resume`. Пик equity и
  счётчик убытков при этом сбрасываются к текущему equity.
- **Порядок проверок.** Бот сначала замечает срабатывание стопа и проверяет equity, затем
  считает модель, и только потом решает, что делать. Закрытие по лимиту выполняется даже тогда,
  когда данные с биржи не прошли проверку.
- **Маленький счёт.** Минимальный лот 0.001 BTC стоит около 83 USDT. Поэтому `MAX_POSITION_USDT`
  и `MIN_EQUITY_USDT` должны оставлять место хотя бы для одного лота, иначе бот не сможет открыть
  позицию.
- Самая надёжная защита — организационная: отдельный субаккаунт только с той суммой, которую не
  жалко потерять, и ключ API **без права вывода средств**.

## Запуск в Docker

Требуется Docker Engine с плагином Compose v2. Все зависимости ставятся в образ:
`python:3.11-slim`, `libgomp1` для CatBoost, `tini`, пакеты из `requirements.txt`.

### 1. Подготовка

```bash
cd trading_bot
cp .env.example .env          # если .env ещё нет; вписать ключи и прокси
chmod 600 .env
mkdir -p runtime && sudo chown 1000:1000 runtime   # контейнер работает от пользователя с uid 1000
```

Если Docker-демон не запущен (`Cannot connect to the Docker daemon`):

```bash
sudo systemctl enable --now docker
sudo usermod -aG docker $USER   # затем перелогиниться, чтобы работать без sudo
```

### 2. Сборка и проверка

```bash
docker compose build
docker compose run --rm bot --once --dry-run    # сигнал модели без ордеров
docker compose run --rm bot --status            # позиция, состояние, лимиты
```

### 3. Запуск

> ⚠️ Одновременно должен работать **только один** экземпляр бота. Если бот уже запущен без
> Docker, сначала остановите его: `kill $(cat bot.pid)`. Каталог `runtime/` общий, поэтому
> контейнер продолжит с того же состояния.

```bash
docker compose up -d
docker compose ps               # STATUS должен стать healthy через 1–3 минуты
docker compose logs -f bot
```

Контейнер перезапускается после сбоев и перезагрузки сервера (`restart: unless-stopped`).
Healthcheck считает контейнер больным, если `runtime/heartbeat` не обновлялся больше 5 минут.

### 4. Управление контейнером

| действие | команда |
|---|---|
| статус и лимиты | `docker compose exec bot python bot.py --status` |
| рубильник: закрыть позицию и остановить торговлю | `docker compose exec bot python bot.py --halt "причина"` |
| возобновить торговлю | `docker compose exec bot python bot.py --resume` |
| логи | `docker compose logs -f bot` или `tail -f runtime/logs/bot.log` |
| остановить бота (позиция и стоп остаются на бирже) | `docker compose stop` |
| обновить код или модель | `docker compose build && docker compose up -d` |
| изменить лимиты в `.env` | `docker compose up -d` (контейнер пересоздаётся с новыми переменными) |

Рубильник можно включить и без `exec`: `touch runtime/HALT` на хосте (возобновление —
`rm runtime/HALT`).

## Запуск без Docker

Бот использует окружение `../.venv` (Python 3.11). Для нового окружения:

```bash
python3.11 -m venv .venv
.venv/bin/pip install -r trading_bot/requirements.txt
```

Модель уже обучена и лежит в `artifacts/`. Чтобы переобучить её и заново проверить перенос
(нужны `../data/btc_1h.csv` и `../data/btc_news.csv`, это около 10 секунд):

```bash
cd trading_bot && ../.venv/bin/python train.py
```

Запуск в фоне:

```bash
cd trading_bot
setsid nohup ../.venv/bin/python bot.py > runtime/logs/stdout.log 2>&1 < /dev/null &
echo $! > bot.pid
```

Такой процесс переживает выход из SSH-сессии, но не перезагрузку сервера. Для автозапуска
используйте Docker или systemd-юнит.

## Настройка: `.env`

| переменная | значение | описание |
|---|---|---|
| `BYBIT_API_KEY`, `BYBIT_API_SECRET` | — | ключ API Bybit (права: Contract — Order, Position) |
| `BYBIT_TESTNET` | `0` | `1` — работать с testnet (нужны ключи testnet) |
| `BYBIT_PROXY` | `http://user:pass@host:3128` | прокси для всех запросов к Bybit |
| `SYMBOL` | `BTCUSDT` | инструмент |
| `LEVERAGE` | `2` | плечо (не выше `MAX_LEVERAGE`), выставляется при старте |
| `POSITION_FRACTION` | `0.95` | доля капитала в позиции |
| `MAX_DRAWDOWN_PCT` … `RISK_CHECK_SEC` | см. таблицу | [ограничения риска](#ограничения-риска) |
| `BOT_RUNTIME_DIR` | `./runtime` | каталог состояния и логов (в Docker — `/app/runtime`) |

Ключ привязан к IP прокси, поэтому без прокси запросы с ключом отклоняются. Для SOCKS5:
`BYBIT_PROXY=socks5h://user:pass@host:1080` плюс `requests[socks]` в `requirements.txt`.
Комментарии в `.env` пишутся на отдельных строках, не после значения.

Параметры стратегии (пороги, `span`, `rebalance`, `sl`) задаются в `strategy.py` и
`artifacts/meta.json`, а не в `.env`: они — результат подбора в ноутбуке.

## Управление

Команды без Docker выполняются из `trading_bot/`. В Docker к ним добавляется префикс
`docker compose exec bot` (или `docker compose run --rm bot` для разовых запусков).

| команда | что делает |
|---|---|
| `python bot.py` | основной режим: итерация сразу, затем раз в час и проверки риска каждую минуту |
| `python bot.py --once` | одна итерация и выход (с реальными ордерами) |
| `python bot.py --dry-run` | без ордеров: только расчёт и логирование сигналов |
| `python bot.py --once --dry-run` | посмотреть текущий сигнал модели, ничего не трогая |
| `python bot.py --status` | позиция, стоп, equity, состояние, метрики риска, лимиты |
| `python bot.py --halt "причина"` | рубильник: работающий бот закроет позицию и остановит торговлю в течение минуты |
| `python bot.py --resume` | снять остановку |
| `python bot.py --test-trade` | проверка исполнения (см. ниже) |

**Проверка исполнения (`--test-trade`).** Бот открывает минимальную позицию 0.001 BTC в сторону
текущего сигнала модели со стопом 3%, проверяет через API, что позиция и стоп стоят на бирже,
и через 3 секунды закрывает её. Затраты около 0.2 USDT. Если на бирже уже есть позиция,
проверка не запускается.

**Остановка.** `kill $(cat bot.pid)` или `docker compose stop`. **Позиция на бирже остаётся
открытой вместе со стоп-лоссом.** Чтобы выйти из рынка, используйте `--halt` (бот сам закроет
позицию) или закройте позицию в интерфейсе Bybit. Если позицию закрыть вручную при работающем
боте, он примет это за срабатывание стопа: перестанет открывать позицию в ту же сторону и
будет ждать смены знака сигнала.

**Перезапуск безопасен.** Состояние лежит в `runtime/state.json` и сверяется с биржей на каждой
итерации. Чтобы начать «с чистого листа», остановите бота, удалите `runtime/state.json` и
запустите снова.

### Как читать лог

```
Свеча 2026-10-01 12:00:00 close=83703.4 | p=0.5214 EWM=0.5044 (пороги 0.4677/0.5378) |
сигнал LONG | цель LONG (пересмотр 2026-09-30 23:00:00) | блок FLAT | риск OK | на бирже LONG 0.001
```

- `Свеча` — время открытия последней закрытой часовой свечи (UTC);
- `p` — вероятность роста от CatBoost, `EWM` — сглаженная вероятность, которая сравнивается с порогами;
- `сигнал` — текущее состояние hold-сигнала (меняется в любой час);
- `цель` — целевая позиция по последней ребалансировке (`пересмотр` — свеча до 00:00 UTC);
- `блок` — сторона, заблокированная после срабатывания стопа (`FLAT` — блокировки нет);
- `риск` — `OK`, `halt` (торговля остановлена) или `pause` (суточная пауза);
- `на бирже` — фактическая позиция и её размер в BTC.

Колонка `action` в `signals.csv` принимает значения `hold`, `open`, `close`, `reverse`,
`vetoed` (действие запрещено риск-менеджером) и `risk_close` (позиция закрыта по лимиту).

## Ограничения стратегии

- **Новостной признак.** Модель обучена с `news_count_168` (число новостей за неделю), но живой
  новостной ленты у бота нет, и признак всегда равен 0. Так же он считался в walk-forward проверке
  ноутбука после конца новостей (04.06.2025), где и получены результаты связки со стопом 3%.
- **Модель почти всё время в лонге** (89–98% времени на отрезках проверки). Основную защиту даёт
  стоп-лосс, а не прогноз: «buy & hold + стоп 3%» даёт +2.8% против +4.3% у CatBoost.
- **Модель не переобучается.** Она обучена на данных до 08.10.2024, пороги слоя зафиксированы.
- **Исполнение отличается от бэктеста.** В бэктесте вход по close сигнальной свечи и комиссия
  0.1%. В реальности вход рыночным ордером через несколько секунд после закрытия свечи, стоп
  отсчитывается от фактической цены входа, есть проскальзывание и funding.

## Безопасность

- `.env` содержит секрет API — не коммитьте и не публикуйте его. Права на файл: `600`. В образ
  Docker он не попадает (`.dockerignore`), переменные передаются через `env_file`.
- Рекомендуется выпустить ключ **без права вывода средств (Withdraw)**, только с правами на
  торговлю контрактами, и оставить привязку к IP прокси.
