# Торговый бот BTC/USDT для Bybit testnet

Бот торгует бессрочным фьючерсом **BTCUSDT** (USDT-маржинальный, `linear`) на
[Bybit testnet](https://testnet.bybit.com). Решения принимают модели из финального ансамбля.
По умолчанию это **RL-агент на вершине ансамбля**: PPO, который видит
прогнозы LogReg, дерева решений и CatBoost. Раз в сутки он выбирает долю капитала от −1
(полный шорт) до +1 (полный лонг).

Как устроены модели и насколько они хороши — в [BOT_README.md](BOT_README.md).

---

## 1. Установка

Нужен Python 3.11. Если окружение `.venv` уже есть, этот шаг можно пропустить.

```bash
python3.11 -m venv .venv
./.venv/bin/pip install --upgrade pip
./.venv/bin/pip install --index-url https://download.pytorch.org/whl/cu126 torch==2.7.1
./.venv/bin/pip install -r requirements.txt
```

Боту видеокарта не нужна: модели маленькие и работают на CPU.

## 2. Ключи API

1. Ссылка для получения ключей для доступа к API [testnet.bybit.com](https://testnet.bybit.com).
2. Ключи хранятся в файле `.env` в корне проекта. Шаблон — `.env.example`:

```ini
BYBIT_API_KEY=ваш_ключ
BYBIT_API_SECRET=ваш_секрет
BYBIT_BASE_URL=https://api-testnet.bybit.com
# HTTPS_PROXY=http://user:pass@host:port   # если Bybit недоступен из вашей страны
```

Ключ должен быть от аккаунта **Unified Trading**, а режим позиций для BTCUSDT — **One-Way**.
На testnet оба значения стоят по умолчанию.

## 3. Обучение моделей

Готовые модели уже лежат в `models/`. Обучать их заново нужно, только если вы обновили данные
или код:

```bash
./.venv/bin/python -m trading_bot.train
# свежие бары можно дописать к истории отдельным CSV (колонки Datetime,Open,High,Low,Close,Volume):
./.venv/bin/python -m trading_bot.train --extra-csv data/new_bars.csv
```

Обучение занимает около 4 минут. В конце выводится таблица результатов на валидации.
Результаты сохраняются в `models/bundle.joblib`, `models/ppo_*.zip` и `models/report.json`.

## 4. Проверка перед запуском

```bash
./.venv/bin/python -m trading_bot.selfcheck
```

Скрипт работает без биржи и проверяет две вещи:
- признаки, посчитанные по окну из 2000 последних баров, совпадают с признаками по всей истории;
- пошаговые решения бота совпадают с политикой агентов при обучении.

В конце должно появиться `OK`.

## 5. Запуск

Команды удобно выполнять в таком порядке:

```bash
# 1) связь и исполнение: купить 0.001 BTC и сразу закрыть (модель не участвует)
./.venv/bin/python -m trading_bot.bot --roundtrip-test

# 2) посмотреть решение модели, не выставляя ордер
./.venv/bin/python -m trading_bot.bot --once --dry-run

# 3) одно решение модели с реальным ордером на testnet
./.venv/bin/python -m trading_bot.bot --once

# 4) постоянная работа
./.venv/bin/python -m trading_bot.bot
```

В постоянном режиме бот просыпается через 15 секунд после закрытия каждого часового бара. Он
загружает свечи, считает прогнозы и записывает их в журнал. Решение агент принимает раз в
24 бара, в 00:00 UTC; в первый запуск — сразу. Между решениями бот только поддерживает целевую
долю капитала. Остановка — `Ctrl+C`. Для работы в фоне:

```bash
nohup ./.venv/bin/python -m trading_bot.bot > logs/nohup.out 2>&1 &
```

После перезапуска бот продолжает с того же места: позиции агентов хранятся в
`logs/bot_state.json`.

### Параметры

| параметр | по умолчанию | смысл |
|---|---|---|
| `--strategy` | `rl_ensemble` | `rl_ensemble` — RL на вершине ансамбля, `rl_position` — RL на признаках ТА, `ensemble` — среднее вероятностей плюс торговый слой |
| `--capital-frac` | `0.5` | какая доля капитала соответствует позиции агента 1.0 |
| `--leverage` | `2` | плечо, которое бот выставляет на бирже |
| `--every` | `24` | решение раз в N часовых баров; `--every 1` — демо-режим с решением каждый час |
| `--decision-hour` | `0` | час UTC для решений при `every=24` |
| `--min-rebalance` | `0.02` | не торговать, если позицию нужно изменить меньше чем на эту долю капитала |
| `--bar-delay` | `15` | через сколько секунд после закрытия бара начинать расчёт |
| `--once` | — | выполнить один цикл с принудительным решением и выйти |
| `--dry-run` | — | считать всё, но ордера не выставлять |
| `--roundtrip-test` | — | проверить исполнение: минимальный лот туда и обратно |
| `--reset-state` | — | сбросить сохранённые позиции агентов |
| `--base-url` | testnet | адрес REST API для ордеров |
| `--data-url` | как `--base-url` | откуда брать свечи; например, `https://api.bybit.com` — реальный рынок |

Часть параметров можно задать в `.env`: `BOT_STRATEGY`, `BOT_CAPITAL_FRAC`, `BOT_LEVERAGE`,
`BYBIT_BASE_URL`, `BYBIT_DATA_URL`.

**Размер позиции.** Целевая позиция в BTC считается так:
`доля агента × капитал × capital-frac / цена`. Например, при капитале 10 000 USDT, доле 0.6 и
цене 64 000 получается 0.6 × 10 000 × 0.5 / 64 000 ≈ 0.047 BTC.

## 6. Журналы

| файл | что внутри |
|---|---|
| `logs/bot.log` | ход работы: прогнозы, решения, ордера, ошибки |
| `logs/decisions.csv` | каждый бар: вероятности роста у трёх моделей и ансамбля, было ли решение, действия сидов, целевая доля |
| `logs/trades.csv` | каждый ордер: сторона, количество, reduceOnly, id, статус, средняя цена, комиссия, позиция до и после, капитал |
| `logs/bot_state.json` | позиции агентов по сидам и время последнего решения |

Ордера бота можно найти в интерфейсе testnet по `orderLinkId`.

## 7. Проверка без доступа к бирже

`mock_bybit/server.py` — локальная имитация Bybit v5. Она проверяет подпись запросов тем же
алгоритмом, что и Bybit, и исполняет рыночные ордера по ценам из `data/btc_1h.csv`.

```bash
# терминал 1: имитация биржи; последние 240 баров спрятаны для перемотки
./.venv/bin/python mock_bybit/server.py --port 8765 --reserve 240

# терминал 2: бот против имитации
export BYBIT_BASE_URL=http://127.0.0.1:8765
./.venv/bin/python -m trading_bot.bot --roundtrip-test
./.venv/bin/python -m trading_bot.bot --once
curl "http://127.0.0.1:8765/mock/advance?bars=24"   # перемотать на сутки вперёд
./.venv/bin/python -m trading_bot.bot --once         # следующее решение
```

Журналы такого прогона сохранены в `logs/mock_demo/`.

## 8. Частые проблемы

| сообщение | причина и решение |
|---|---|
| `заблокировал запрос по стране IP-адреса (HTTP 403)` | Bybit не обслуживает IP из вашей страны (например, из США). Запустите бота с сервера в другой стране или укажите `HTTPS_PROXY` в `.env` |
| `нет BYBIT_API_KEY / BYBIT_API_SECRET` | нет файла `.env` или в нём пустые ключи |
| `retCode=10003` | неверный ключ, или ключ от mainnet, а бот работает с testnet |
| `retCode=10004` | неверный секрет (ошибка подписи) |
| `retCode=10002` | часы расходятся с сервером; бот синхронизируется сам, а если ошибка повторяется — включите NTP |
| `retCode=110007` / `110004` | недостаточно средств: запросите тестовые USDT или уменьшите `--capital-frac` |
| `retCode=10005` | у ключа нет прав на ордера и позиции по контрактам |
| `изменение меньше порога — ордер не нужен` | это не ошибка: позиция уже близка к целевой |

## 9. Структура проекта

```
trading_bot/
  config.py        настройки и параметры моделей из ноутбука
  features.py      признаки технического анализа (разделы 2–7 ноутбука)
  signals.py       бэктест, торговый слой, RL-среда (разделы 9–11, 19)
  train.py         обучение моделей → models/
  strategy.py      живой инференс: свечи → целевая позиция
  bybit_client.py  REST-клиент Bybit v5
  bot.py           цикл бота и исполнение ордеров
  selfcheck.py     офлайн-проверка
mock_bybit/server.py   имитация Bybit для тестов
models/                обученные модели и отчёт
logs/                  журналы работы
```
